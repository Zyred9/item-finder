# 寻物记 - 需 AI 分析的功能清单与模型推荐

本文档列出需要大模型 / 多模态能力的业务功能、所需能力类型（音频 / 视频 / 图片理解 / OCR / 纯文本），以及推荐模型。

---

## 一、功能与所需能力总览


| 功能         | 说明                          | 所需能力类型                   | 当前状态         |
| ---------- | --------------------------- | ------------------------ | ------------ |
| 对话找物意图理解   | 用户输入「护照在哪」→ 理解意图、抽取关键词并查库   | **纯文本 LLM**（可选，当前为关键词规则） | 规则实现，可升级 LLM |
| 聊天记录压缩总结   | 多轮对话 → 生成一段简短总结             | **纯文本 LLM**              | 已接入 DeepSeek |
| 语音转文字（ASR） | 找物/存物页录音 → 转成文字填表单或发消息      | **音频 · 语音识别 (ASR)**      | 后端 TODO，待接入  |
| 文字转语音（TTS） | 搜索结果 / 回复 → 语音播报            | **音频 · 语音合成 (TTS)**      | 后端 TODO，待接入  |
| 存物主图理解     | 拍物品照 → 识别物品/场景，建议名称、分类      | **图片理解 (Vision)**        | 未实现          |
| 扩展凭证照 OCR  | 拍说明书/发票/药盒 → 提取文字、品牌、型号、日期等 | **OCR（文字识别）**            | 未实现          |
| （可选）以图搜物   | 拍一张图 → 在库中找相似物品             | **图片理解 + 向量检索**          | 未实现          |

## 二、按能力类型拆解与推荐模型

### 1. 纯文本 LLM（对话、总结、意图）


| 能力用途      | 说明                        | 推荐模型                        | 备注                  |
| --------- | ------------------------- | --------------------------- | ------------------- |
| 聊天记录压缩总结  | 多轮对话 → 一段话总结              | **DeepSeek**（已用）            | 性价比高、中文好            |
| 对话找物意图/槽位 | 用户说一句话 → 意图 + 实体（物品名、位置等） | **DeepSeek / Qwen / GLM-4** | 可复用同一接口，或单独小模型做 NLU |
| 通用对话/兜底回复 | 无法匹配时的自然回复                | 与上面同一文本模型即可                 | -                   |


**推荐优先级（文本）：**

- **DeepSeek**：已接入，适合总结与对话，价格友好。
- **通义千问 (Qwen)**：中文好，API 稳定，可作为备选或升级。
- **GLM-4 (智谱)**：中文对话不错，适合做意图理解。

---

### 2. 音频 · 语音识别 (ASR)


| 功能       | 说明                  | 推荐模型/服务     | 备注           |
| -------- | ------------------- | ----------- | ------------ |
| 找物页语音输入  | 按住说话 → 转文字发问        | **百度短语音识别** | 文档已提及，中文场景成熟 |
| 存物页主表单语音 | 说「吹风机放主卧抽屉」→ 填名称、位置 | 同上          | 可加一句话识别      |
| 扩展信息语音补充 | 录音 → 转文字填入扩展说明      | 同上          | 同上           |


**推荐优先级（ASR）：**

- **百度智能云 · 短语音识别**：中文场景常用，按次/按时长计费，易集成。
- **讯飞开放平台 · 语音听写**：中文准确率高，多端 SDK。
- **阿里云 · 语音识别**：适合已有阿里云体系的团队。
- **OpenAI Whisper（自建/开源）**：可私有化，需自备算力或第三方托管。

---

### 3. 音频 · 语音合成 (TTS)


| 功能     | 说明                 | 推荐模型/服务             | 备注     |
| ------ | ------------------ | ------------------- | ------ |
| 找物结果播报 | 将「护照在保险柜第二层」等结果读出来 | **百度 TTS / 讯飞 TTS** | 中文自然度好 |
| 对话回复播报 | 将 AI 回复转为语音播放      | 同上                  | 同上     |


**推荐优先级（TTS）：**

- **百度智能云 · 语音合成**：与百度 ASR 同平台，对接简单。
- **讯飞开放平台 · 语音合成**：多发音人，适合播报场景。
- **Edge TTS（微软）**：部分场景免费，音质不错，需注意合规与可用性。

---

### 4. 图片理解 (Vision)


| 功能       | 说明                         | 推荐模型                           | 备注      |
| -------- | -------------------------- | ------------------------------ | ------- |
| 存物主图理解   | 用户拍物品照 → 识别物品类型、场景，建议名称/分类 | **Qwen-VL / GLM-4V / 通义千问-VL** | 多模态大模型  |
| （可选）以图搜物 | 拍照 → 与库内物品图片相似度检索          | **视觉模型提取特征 + 向量库**             | 需建图向量索引 |


**推荐优先级（图片理解）：**

- **通义千问-VL (Qwen-VL)**：阿里，中文多模态强，API 可用。
- **GLM-4V (智谱)**：中文理解好，支持多图。
- **DeepSeek-V2/V3（若开放多模态）**：与现有 DeepSeek 文本统一。
- **百度视觉理解 / 腾讯云视觉**：若更偏向云服务、少自研模型可考虑。

---

### 5. OCR（文字识别）


| 功能        | 说明                           | 推荐模型/服务                         | 备注                |
| --------- | ---------------------------- | ------------------------------- | ----------------- |
| 扩展凭证照 OCR | 拍说明书、发票、药盒、保修卡 → 提取品牌、型号、日期等 | **PaddleOCR / 百度 OCR / 腾讯 OCR** | 结构化信息可再喂给 LLM 抽字段 |


**推荐优先级（OCR）：**

- **PaddleOCR（开源）**：可私有化部署，表格、版面分析好，适合说明书/发票。
- **百度智能云 · 通用/高精度 OCR**：中文场景成熟，按次计费。
- **腾讯云 · 通用印刷体/手写体 OCR**：适合已有腾讯云。
- **通义 · 文档 OCR**：与通义 LLM 同体系，便于后续“OCR + LLM 抽字段”一条龙。

---

### 6. 视频（暂无规划，仅作扩展参考）


| 功能         | 说明                  | 所需能力              | 推荐方向                        |
| ---------- | ------------------- | ----------------- | --------------------------- |
| （可选）扫房间/柜子 | 短视频或连续帧 → 识别多个物品及位置 | **视频理解 或 多帧图像理解** | 成本高，可先不做；若做可考虑多帧抽帧 + 图像理解模型 |

## 四、实施建议

1. **已具备**：纯文本 LLM（DeepSeek）用于聊天总结；对话找物目前规则即可，后续可改为 LLM 意图。
2. **优先补齐**：语音能力（ASR + TTS），用百度或讯飞即可覆盖找物/存物/播报。
3. **其次**：存物主图理解（Qwen-VL/GLM-4V）提升录入体验；扩展凭证 OCR（PaddleOCR 或云 OCR）提升药品/电器等结构化信息录入。
4. **可选**：以图搜物、视频理解留到后续迭代再选型。

若你确定优先做哪几项（例如：先 ASR+TTS，或先图片理解），可以再细化接口设计与调用方式。
